# DSH Host compatibility report (Phase 0 baseline)

Status: **measured**, Phase 0 baseline for task `DSH-PILOT-20260912`.
Bridge version under construction: none yet (this document precedes implementation).
Owner: company DSH worker on route `sx-anthropic/deepseek-flash`.

This report is the compatibility gate for the MCP bridge. It records what the DSH Host
actually exposes, what the bridge may rely on, what it must treat as unknown, and how the
version pin is established. Every claim below is either *measured* on this machine or
*read* from the installed package's own contract types; the two are labelled separately.

## 2. Version pin — and why `host.describe.version` cannot be it

### 2.1 Measured facts

| Source | Version |
|---|---|
| `@deepseek-ai/dsh/package.json` (installed) | `0.1.1-rc.2` |
| `host.describe` on the live Host | `"version": "0.0.1"` |
| `host.describe` on the freshly booted isolated Host | `"version": "0.0.1"` |
| Filesystem install date of the installed tree | 2026-08-25 |
| `@deepseek-ai/dsh-host-apiproxy` installed | `0.1.1-rc.2` |
| `@deepseek-ai/dsh-host-apiproxy` on npm | `next = 0.1.1-rc.2` (published 2026-08-21), `latest = 0.0.1-rc.1` |
| npm `dist-tags` for `@deepseek-ai/dsh` | `latest = 0.1.5-rc.1`, `next = 0.1.5-rc.2`, `alpha = 0.1.5-alpha.2` |

**`host.describe.version` reports `0.0.1` for both a long-lived host and a freshly booted
one, while the installed launcher package is `0.1.1-rc.2`.** The field is a placeholder
value, not a compatibility pin. Any bridge that gates behaviour on it would be gating on a
constant. This is a hard constraint on the design, not a cosmetic quirk.

### 2.2 The pin this project will use

The pin is a tuple, checked in and regenerated by a script, never inferred from the Host:

1. `@deepseek-ai/dsh` launcher version (`0.1.1-rc.2`).
2. The resolved dependency tree: all `@deepseek-ai/*` package versions actually present.
   Measured on this machine: **452 packages walked, 196 of them `@deepseek-ai/*`; 187 at
   `0.1.1-rc.2`**, plus `@deepseek-ai/cordis@4.0.1`, `@deepseek-ai/schemastery@3.18.1`, and
   single packages at `0.1.1`, `1.0.1`, `1.0.2`, `1.0.6`, `1.0.16`, `1.1.3`, `1.8.2`.
   The non-uniform tail is exactly why a launcher version alone is insufficient.
3. Runtime deps the bridge may meet: `zod@4.4.3`, `ws@8.21.3`, `@modelcontextprotocol/sdk`
   (declared `^1.12.0` by `@deepseek-ai/dsh-mcp-client`).
4. Verified artifact integrity: the published `@deepseek-ai/dsh-host-apiproxy@0.1.1-rc.2`
   tarball fetched from the public registry is
   `sha256 b0de1779714a822ba712d46bcf71c141807d79d3e3918d3128b22558262917b5`
   (194 643 bytes), integrity
   `sha512-dplRnGGXXsQYFQ1KMHymAM0iaxuE9Z153JHYcGEgOwXNkS3HA20gSi3yMt6fz+zi/cMHYXvY1JQhS54BTc761A==`.
   The installed tree's contract types match this artifact.

Re-pin procedure (mandatory, not optional): re-run the inventory script, diff the
`RpcMethodMap` keys and the frame unions against the previous pin, and let the
compatibility contract test (`CT-*`, see `docs/test-matrix.md`) fail loudly on any
add/remove/rename. A model cannot be asked to "be careful about versions"; the test does it.

### 2.3 Measured contract drift between published versions

The `/api` surface is **not stable across published versions**. Diffing the published
`rpc-map.d.ts` of `0.0.1-rc.1` against `0.1.1-rc.2`:

- removed: `command.execute`, `command.list`
- added: `workspace.insertBefore`

Consequences the bridge design must absorb:

- capability negotiation happens at runtime (probe + declared support set), never by
  version comparison;
- an operation whose contract is absent must fail as **unsupported**, visibly, with the
  observed reason — never be silently emulated.

## 3. Transport surface (measured)

| Carrier | Path | Method | Measured result |
|---|---|---|---|
| Unary RPC | `/api/<method>` | `POST` | 200, body `{type:"server-response", rpcId, result}` |
| Approval/question answers | `/api/respond` | `POST` | 200, body is a **carrier receipt**: `{"accepted":false,"reason":"not-pending"}` for an unknown `rpcId` |
| Mux downlink (all sessions) | `/api/events.mux` | `GET` + Upgrade | plain `GET` → **426** `upgrade required`; WebSocket only |
| Host downlink | `/api/events.host` | `GET` + Upgrade | same carrier |
| Session-log export | `/api/session.export` | `GET`/`HEAD` | route present in `handler.js`; not probed for content |
| Anything else under `/api` | — | — | 404 `not found`; non-`POST` unary requests are rejected |
| Outside `/api` | — | — | 404 `not found` (`paths outside /api/ return 404`) |

Structural facts read from the contract types:

- **Upstream traffic is HTTP only.** `WebSocketDownlinks` documents client messages on the
  WebSocket as "a protocol violation"; all client→host traffic rides `POST`.
- The downlinks carry the *whole* host state; there is no per-session subscription method.
- `rpcId` is minted by the initiator. Client requests mint their own; a `client-response`
  **echoes** the server-request's `rpcId` and never mints one.
- Unary methods never throw business errors: they return `result.ok === false` with a
  closed-set `error.code` (49 codes, `RpcErrorDetailsMap`) and details. Transport failures
  are folded into the same shape via `transportError()` with code `internal`.
- Every response is parsed and the `rpcId` echo is verified; a frame that fails either
  parse level is **skipped**, not fatal (SSE/WS decode path). A bridge therefore must do
  its own gap detection — the carrier will not tell it that something was dropped.

### 3.1 Trust fence (read from contract, and it matters for tests)

`isTrustedApiRequest` guards **every** `/api` request using the `Host` header (and Origin /
Fetch-Metadata when a browser attaches them). Its own documentation states plainly that it
"is not an auth layer" and that network reachability is out of scope — binding policy belongs
to the webserver config. The bridge must therefore:

- connect to loopback (or a declared `trustedHosts` authority) and send a correct `Host`;
- never treat reachability as authorization, and never claim the bridge "authenticates" to
  the Host;
- record the Host authority in its own durable state so a later reconnect cannot be
  silently redirected to a different authority.

## 4. Operation inventory (read from `RpcMethodMap` at the pin)

49 client-request methods. The map is the single source of truth; payload types are derived
from these signatures, so the bridge's typed client can be generated/checked against it.

| Domain | Methods |
|---|---|
| session | `list`, `search`, `create`, `history`, `models`, `selectModel`, `rename`, `fork`, `prompt`, `attachment`, `updateQueue`, `cancel` |
| subagent | `list`, `history`, `prompt`, `interrupt` |
| host | `describe`, `pickDirectory`, `listDirectory`, `createDirectory`, `openPath` |
| workspace | `list`, `create`, `rename`, `delete`, `insertBefore`, `insertSessionBefore`, `archiveSession` |
| skill | `list` |
| agentPreset | `list`, `select`, `read`, `copy`, `openDocument`, `remove` |
| goal | `create`, `edit`, `pause`, `resume`, `complete`, `clear` |
| settings | `describe`, `openDocument`, `update`, `replace`, `mutate` |
| credentials | `describe`, `set`, `unset` |
| llm | `providers`, `models`, `discoverModels` |
| (not in map) | `respond` — approval/question answers, on `POST /api/respond` |

Stream frames: `MuxFrame` = `session/event`, `session/subscribed`, `approval/requested`,
`approval/resolved`, `question/requested`, `question/resolved`, `session/queue`,
`session/jobs`, `session/projection`, `stream/error`. `HostFrame` = `host/session-added`,
`host/session-removed`, `host/session-status`, `host/agent-error`, `host/workspace-changed`,
`host/workspace-removed`, `host/workspace-order-changed`, `host/archived-sessions-changed`,
`host/remote-event`, `stream/error`.

Key semantics the bridge depends on (contract text, condensed but not paraphrased into
something stronger than it says):

| Operation | Semantics that matter to the bridge |
|---|---|
| `session.create` | At most one of `workspaceId`/`cwd`. **A caller may preallocate `sessionId`: retries with the same id and cwd return the same session; a different cwd fails `session-conflict`.** This is the only measured upstream idempotency affordance. |
| `session.list` | `updatedAt`-descending. **`cursor` is "a reserved seat, unimplemented"** — v1 returns everything. |
| `session.history` | Windowed by `beforeSeq` + `maxMessages`; page boundaries always align to whole messages, never cut mid-message. Tail page additionally carries the in-flight partial and the `projections` block. Reading history "never resumes or publishes an Agent". |
| `session.prompt` | `mode: 'queue'` \| `'steer'`. Durable host admission **before** the model sees it. A single text block starting with `/` is a slash command executed by the host and **never sent to the model** — a bridge that forwards arbitrary caller text can therefore trigger host commands; that must be a deliberate policy decision. Returns `{accepted:true}`; a command may return `command:{kind:'success'}`. Subagents reject `agent-busy`. |
| `session.updateQueue` | Mutates one **pending** occurrence by `MessageId` (`edit`/`remove`/`steer`). The id comes from the `session/queue` frame; ids are not durable until the agent claims the message. |
| `session.cancel` | "Stops an ordinary session's active turn, **preserving pending inbox work that resumes in FIFO order after cancellation settles**." Cancelling the queue is a *different* operation (`updateQueue` remove). |
| `session.fork` | Cuts at the first `turn/end` at or after `atSeq`; open turn → `fork-unavailable` rather than a clipped earlier turn. |
| `session.rename` | Appends a `session/title` event with `user` source, which **pins** the title against regeneration. |
| approvals | `POST /api/respond` echoes the `approval/requested` frame's `rpcId` with `{sessionId, approvalId, outcome:'allowed-once'\|'rejected'}`. The HTTP body is only a receipt: `not-pending` means the request was already resolved/expired/replayed. The *outcome* arrives later in `approval/resolved`. |
| questions | Same carrier; answers one `ask()` as a whole batch. Answer payload carries no resource id — `rpcId` is the correlation. |
| `events.mux` | On open: a `session/subscribed` frame per attached session (`lastSeq`), then **replays each session's still-pending approval/question requested frames with the original `rpcId` reused verbatim** ("the refresh-recovery baseline"). `since` is "unimplemented in v1 (ignored if passed)"; reconnection = reopen the stream **and refetch history**. |
| event loss | A frame that fails to parse is reported and skipped, and the client's own gap detection "covers whatever the frame carried". Gaps are the bridge's problem. |

## 5. Supported / unknown / unsupported matrix

"Supported" = measured or contract-guaranteed at the pin. "Unknown" = the contract does not
promise it and it was not measured; the bridge must treat it as unsupported until a test
proves otherwise. **No row marked Unknown may be claimed as working in any report.**

### 5.1 Supported

| Capability | Evidence | Bridge use |
|---|---|---|
| Unary RPC over `POST /api/<method>` + rpcId echo | measured 200 + `result.ok:true` | base carrier |
| `host.describe` (cwd/provider/model/attachedSessions/home/canOpenPath) | measured | identity/probe; **not** the version pin |
| `session.list` | measured (38 sessions on the live host; 0 on a fresh isolated host) | discovery — restricted to owned ids |
| `session.create` with preallocated `sessionId` | contract | idempotent session creation/retry |
| `session.history` paging (`beforeSeq`, `maxMessages`) | contract | incremental event paging |
| `session.prompt` with `mode: queue`/`steer` | contract | message dispatch |
| `session.cancel` (turn scope) | contract | turn cancellation |
| `session.updateQueue` (queue scope) | contract | queue cancellation/mutation |
| WS mux + host downlinks; `426` on plain GET | measured | event ingest |
| Pending-approval replay on mux open (same `rpcId`) | contract | reconnect recovery baseline |
| `POST /api/respond` echo contract + `not-pending` receipt | measured (`{"accepted":false,"reason":"not-pending"}`) | approval/question answering, stale-response detection |
| Isolated Host fixture: throwaway `DSH_HOME`, `dsh web --port 0 --host 127.0.0.1 --no-open` | **measured**: booted, `host.describe` answered, `session.list` = 0, killed cleanly with no leftover process | test fixture for real-Host layers |

### 5.2 Unknown — must be treated as unsupported until a test proves it

| Unknown | Why it is unknown | Consequence |
|---|---|---|
| Whether `session.prompt` survives a bridge crash without duplicate dispatch | no host-side idempotency key beyond the request's `rpcId`, and no dedupe method in the map | the bridge must record intent durably **before** sending and reconcile after restart; never blind re-send |
| Whether a `sessionId` can be re-attached by a *different* process and driven concurrently | nothing in the contract arbitrates two live callers on one session | competing-owner protection must be local, atomic, and cooperative |
| Whether `attachedSessions` counts prove wakefulness of *our* session | it is a count, not a set | connection state ≠ execution state; needs a per-session oracle |
| Whether cancelling a turn stops tool **subprocesses** | `session.cancel` speaks about the turn and inbox, never about child processes | never report subprocess stop without process-level evidence (PID/exit oracle) |
| Whether `mux` ordering is total across reconnects and whether frames can be dropped without a `stream/error` | contract says parse failures are skipped; `since` is unimplemented | bridge-side cursor + gap detection + refetch-history reconciliation |
| Whether `session/queue` item ids are stable across reconnect | ids exist only while the item is pending | queue mutations must be re-derived from a fresh snapshot |
| Whether approval frames can arrive for sessions the bridge does not own | mux is all-session aggregated | approval binding must check task/turn/rpcId, not just sessionId |
| Whether the Host enforces any bound on event/attachment size | not stated anywhere read | bridge must impose its own caps and treat oversize as a first-class outcome |

### 5.3 Unsupported at this pin (measured absent, not "not yet tried")

| Unsupported | Evidence |
|---|---|
| Cursor-based `session.list` pagination | contract: "cursor is a reserved seat, unimplemented" |
| Mux `since` resume | contract: "unimplemented in v1 (ignored if passed)" |
| Any upstream channel on the WebSocket | contract: client messages are a protocol violation |
| Any authentication/authorization layer for `/api` | contract: the trust fence "is not an auth layer" |
| Any dependency-free protocol-version handshake | `host.d.ts`: "No protocol version: client and host ship together" |
| `command.execute` / `command.list` | absent from `RpcMethodMap` at the pin (present in `0.0.1-rc.1`) |
| A Host-observable stop receipt for tool subprocesses | no such method or frame in the contract |

### 5.4 Bridge-side capability items that have no Host counterpart

These are *bridge* features whose correctness rests on the bridge's own storage and on
process-level observation; the Host cannot be asked to confirm them:

persistent task/session/turn/operation/interaction IDs; the durable journal and its
reconciliation rules; atomic single-owner protection; storage-corruption / disk-full /
permission behaviour; approval binding to task+turn+rpc; and the distinction between
"connection lost" and "execution unknown".

## 6. Fixture feasibility (measured today)

| Fixture | Status | Evidence |
|---|---|---|
| Isolated official DSH Host, throwaway home | **feasible** | `DSH_HOME=<tmp>/home dsh web --port 0 --host 127.0.0.1 --no-open` → `dsh web: http://127.0.0.1:<ephemeral>`; profile auto-initialized (`profiles/web` + `storages`); `host.describe` ok; `session.list` = 0 items; process killed with no leftovers |
| Per-test-home isolation | feasible | the fresh home created only `storages/workspace.json` and `profiles/**` |
| Provider override for the fixture | **planned, not yet proven** | the user's real home configures providers under a settings namespace (`llm-pi-ai.providers.<id>` with `apiKeyEnv` + `baseURL` + `models[]`), so a mock provider route can be declared in an isolated home's patch layer (`cordis.patch.yml`, currently `[]`) while credentials stay by env reference only |
| Port safety | measured | `--port 0` delegates to the OS; the live UI's port 3080 was never contacted by the fixture and remains untouched |

**Fixture vs fake Host are different things and are never interchangeable:** the fake Host
(section 4 carrier, implemented in-process) tests the bridge's own protocol robustness; the
isolated official Host tests that the bridge's assumptions match the real product. A green
fake-Host suite proves nothing about the official Host, and this report does not claim it does.

## 7. Blocking unknowns for implementation (Phase 0 checkpoint)

1. **Mock-provider feasibility** for layer `S6`: the isolated home must be able to name a
   provider route whose endpoint is a local fixture (no company URL, no real key). Read from
   settings structure: plausible; not yet proven by a running turn.
2. **Whether an isolated Host can complete a turn with zero paid calls** — required before
   any automated turn-level test can join default CI. Until proven, turn-level suites stay
   opt-in.
3. **Subprocess stop evidence** for cancellation claims: needs a real child-process oracle
   (the tool surface decides how a process can be observed); no Host receipt exists.

None of these block the rest of the design; each is listed so it cannot be quietly assumed
away.
